# 米诺战略参谋部 · 天势小程序 V3（精简版）— 设计与实施规划方案

> 状态：**方案（仅规划，未实施）**
> 依据：设计交接包（claude.ai/design 项目「mino小程序设计方案」，主参考稿 `米诺 V3 · 精简版.dc.html` + 交接文档）、设计稿逐屏分析（见 `docs/research/design-analysis.md`）、代码库现状调研。
> 日期：2026-07-10

---

## 1. 结论摘要

- **绿地项目**：`pokocat/mino` 仓库为空（零提交），V3 是从零搭建，不存在旧代码迁移或删减工作。「精简」是相对 V2 设计稿而言的产品范围收敛。
- **产品只有一条闭环**：收到「今日一问」→ 跟米诺（LLM）聊透 → 生成 Markdown 报告进「报告库」→ 微信通知 → 回来接着聊，米诺越来越懂你。**对话是唯一引擎，报告是唯一交付物。**
- **技术上零自研算法**：对话与记忆全部依托 FastGPT（应用 + 每用户知识库 + 报告工作流），自有后端只做鉴权、代理转发、CRUD、定时任务和推送。
- **推荐栈**：微信原生小程序（TypeScript）+ NestJS/Prisma/PostgreSQL/Redis/BullMQ + FastGPT。
- **最大三个风险**：① 衬线字体（Noto Serif SC）在小程序内无法完整加载，需降级策略；② SSE 流式在小程序端依赖 `wx.request` 的 `enableChunked`，真机兼容需尽早验证；③ AI 生成内容的合规（生成式 AI 备案、内容安全审核、小程序类目资质），需与开发并行推进。

## 2. 产品范围

### 2.1 范围内（V3 全部功能）

| 模块 | 内容 |

## 3. 技术选型（决策）

| 层 | 选型 | 理由 |
|---|---|---|
| 小程序前端 | **微信原生小程序 + TypeScript + Sass**（glass-easel/Skyline 不强制） | 无跨端需求；SSE 依赖 `wx.request enableChunked`，原生控制最直接；包体小、审核路径熟悉。不选 Taro/uni-app：抽象层对 chunked 响应与自定义 tabBar 的支持反而添堵 |
| Markdown 渲染 | **towxml**（自定义主题）+ 轻量「报告版式解析器」 | towxml 是小程序最成熟的 Markdown 渲染库；报告的特色版式（4px 竖色条小节、壹贰叁步骤、首字下沉、批注块）用自定义解析映射到组件实现（见 §7.4） |
| 后端 | **Node.js 20 + NestJS + Prisma** | 交接文档建议 Node/NestJS 或 Go；Nest 的模块化 + SSE 支持 + 生态（BullMQ、Passport-JWT）契合本项目全部需求，团队上手成本低于 Go |
| 数据库 | **PostgreSQL 16**（Prisma 管理迁移） | 交接文档建议；5–7 张表规模，JSONB 可承接报告元数据 |
| 缓存/队列 | **Redis 7 + BullMQ** | streak 计数、报告生成异步 job、今日一问 cron 派发、推送重试 |
| LLM 引擎 | **FastGPT**（自托管优先，商业云备选） | 产品灵魂即「V6.0 米诺提示词 + 每用户知识库 + 报告工作流」，全是 FastGPT 自带能力；自托管便于按 user 建知识库、控制成本与数据（部署方式见 §11 开放问题） |
| 部署 | Docker Compose（后端 + Postgres + Redis + FastGPT），单台云服务器起步 | 用户量前期小；后续可拆 |

## 4. 系统架构

```
微信小程序 (原生 + TS)
  ├─ 米诺 tab：对话页 ────── SSE(enableChunked) ──▶ ┐
  ├─ 报告库 tab：列表/详情 ── REST ────────────────▶ │  自有后端 (NestJS)
  └─ 登录/入局 ───────────── REST ────────────────▶ ┘
                                                      │
        ┌─────────────────────────────────────────────┤
        │  AuthModule      code2session → JWT；入局 profile
        │  ChatModule      建会话；转发 FastGPT Chat API（注入 chatId/uid），SSE 透传
        │  ReportModule    生成(异步 BullMQ job → FastGPT 报告工作流)；CRUD；已读/计数
        │  TaskModule      cron 生成今日一问；订阅消息推送（报告完成/今日一问）
        │  StreakModule    Redis 记连续天数（Asia/Shanghai 日界）
        │  SafetyModule    用户输入 msgSecCheck；LLM 输出审核钩子
        └───────────┬───────────────┬────────────────
                    ▼               ▼
              PostgreSQL       FastGPT
              (5+2 张表)        ├─ 米诺应用（V6.0 浓缩提示词，势/节奏比喻叙事，不排盘）
              Redis/BullMQ      ├─ 每用户知识库（写入对话要点 → 检索 = 越来越懂你）
                                └─ 「总结成报告」工作流（对话+知识库 → Markdown）
```

关键原则：
- 小程序**不直连** FastGPT，一切经自有后端（鉴权、限流、注入用户标识、内容安全、计费可控）。
- 报告生成是**后台任务**：设计稿弹层文案「你可以先回去接着聊」即此语义。前端拿 `report_id` 后轮询状态或等推送，不阻塞对话。
- 知识库写入是**异步旁路**：对话结束/报告生成后由 job 提取要点写入，不在对话链路上加延迟。

## 6. API 设计（修订版）

基线为交接文档 §7，补充异步生成、已读、计数：

```
# 鉴权 / 入局
POST /auth/wx-login              {code} → {token, isNewUser}
POST /me/profile                 {nickname, industry, biz_note}
GET  /me                         → 用户信息 + streak_days + 报告计数摘要

# 对话
POST /conversations              → {conversation_id, fastgpt_chat_id}
GET  /conversations?limit=       历史会话列表（对话页恢复上下文用）
GET  /conversations/:id/messages
POST /conversations/:id/messages {content} → SSE（transfer-encoding: chunked）
     流事件：token(增量文本) / suggestions(建议气泡数组，含 action=generate_report 项)
            / report_offer(米诺主动提出写报告) / done

# 报告（异步生成）
POST /reports/generate           {conversation_id, type} → {report_id, status:'generating'}
GET  /reports/:id                → 详情（status/body_md/annotation/sources[]…）；前端可轮询至 ready
GET  /reports?type=&cursor=      列表（含 is_read）
GET  /reports/stats              → {total, by_type{}, unread}
POST /reports/:id/read           标记已读（消除「米诺刚写好」描边）
POST /reports/:id/chat           「跟米诺聊这份报告」→ 新建 conversation，注入报告上下文
POST /reports/:id/append         「跟米诺补充」→ 回对话续写后更新报告（并 report_sources 追加）
GET  /reports/:id/export         导出（Markdown 文本 / 分享图，见 §9.4）

# 任务 / streak
GET  /tasks/today                今日一问（无则返回 null，前端隐藏卡片）
POST /tasks/:id/start            → {conversation_id}（注入 prompt_seed 为开场，task→started）
GET  /me/streak

# 后台（非公开 API）
cron 08:30 Asia/Shanghai：为活跃用户生成 daily_q + 订阅消息推送
BullMQ：report.generate（调 FastGPT 工作流）→ 成功置 ready + 推送；失败置 failed + 可重试
        kb.ingest（对话要点/报告要点写入用户知识库）
```

SSE 端到端约定：后端从 FastGPT 收流后**透传增量**，同时缓冲全文；流结束落 `messages`、异步触发 `kb.ingest`、判断是否发出 `report_offer`（见 §8.4）。

### 7.3 设计 token 落地

- 以 `styles/tokens.scss` 单一来源：色板（朱砂 `#B23A2E`、描金 `#9A7B3F`、金字 `#E8C77A`、墨 `#1F1B16`/`#574F44`/`#6B6256`/`#9B9384`、纸 `#F6F1E5→#E6DCC9`、卡面 `#FBF7EF`、tab 面 `#EDE5D3`、类型四色、微信绿 `#07C160`）、圆角、阴影、间距。设计稿 px 按 750 设计基准换算 rpx（稿宽 388px ≈ iPhone 逻辑宽，1px ≈ 1.93rpx，取整规则写入 tokens 注释）。
- **字体策略（风险 R3 的决策）**：正文/UI 用系统字体栈；衬线观感通过 `wx.loadFontFace` 加载**子集化**的 Noto Serif SC（只含标题高频字 + 数字，woff 控制在 ~1–2MB、CDN 提供）；加载失败降级系统字体，版式不依赖字体度量。Space Mono 仅用于数字/时间，子集极小可内置。首字下沉、壹贰叁等以布局实现，不依赖字体特性。

### 7.4 报告渲染策略（决策）

`reports.body_md` 是**唯一事实源**（便于导出、分享、回喂知识库）。但为还原设计版式（4px 竖色条小节标题、壹贰叁步骤、批注块、首字下沉），约束 FastGPT 报告工作流输出**受限 Markdown 规范**：

- `## 小节名` → 竖色条 + 衬线小节标题（色条颜色按小节序号轮换类型色板）
- 有序列表前三项 → 壹/贰/叁步骤条
- `annotation` 独立字段，不混入 body_md → `annotation-block`
- type=resume：正文按段渲染衬线正文 + 首段首字下沉

前端 `md-report` 用 towxml 解析 AST 后做规则映射；规范外的 Markdown 按 towxml 默认主题兜底渲染（保证任何 LLM 输出都能读）。

## 8. FastGPT 集成设计

### 8.1 米诺应用
- system prompt = 「⽶诺战略参谋部 · 天势终极版 V6.0」浓缩版（设计项目 `米诺对话（可对话）.dc.html` 内含可直接取用的浓缩版）。保留：势哲学、角色语气、术语→比喻翻译表、禁用词（赋能/抓手/底层逻辑…）、埋钩子、十二问、复盘流程；删除：一切排盘与精确数字输出。
- 应用参数：开启知识库检索（当前用户 kb）、开启对话建议（或由后端二次调用生成 suggestions，见 8.3）。

### 8.2 每用户知识库
- 用户首次入局时经 FastGPT OpenAPI 创建专属知识库，`users.kb_id` 记录；对话/报告要点由 `kb.ingest` job 写入（要点抽取用一个轻量总结提示）。
- 隔离即隐私边界：检索只挂当前用户 kb。

### 8.3 suggestions
- 首选：FastGPT 应用自带「猜你想问」；若样式/可控性不足，后端在每轮流结束后追加一次轻量补全生成 3 条（其中生成报告项固定注入，action=generate_report + 推荐 type）。

### 8.4 米诺主动写报告（触发判定 · 决策）
不做隐式启发式。采用**显式信号**：米诺 system prompt 中约定——当判断「一件事聊透了/到复盘时点」，在回复末尾输出结构化标记 `<mino:report_ready type="strategy" topic="…"/>`（前端不展示，后端拦截）。后端收到标记即入队 `report.generate(origin='agent')`，完成后推送「米诺刚写好一份…」。误触率通过提示词约束 + 每日 origin=agent 上限（如 1 份）控制。

### 8.5 报告工作流
输入：`{type, 该对话消息, 用户知识库检索片段, 用户画像(industry/biz_note)}` → 输出 JSON：`{title, body_md(受限规范), annotation, word_count}`。后端校验规范、落库、回喂 kb、推送。

## 9. 关键技术方案与风险应对

| # | 风险/难点 | 对策 |
|---|---|---|
| R1 | 小程序 SSE：`wx.request` 需 `enableChunked:true`，onChunkReceived 返回 ArrayBuffer、分包边界不齐 | 后端按行（`data:…\n\n`）发事件；前端做 UTF-8 安全拼接缓冲区按 `\n\n` 切帧；**M2 第一周真机验证 iOS/Android**；兜底方案：降级为分段轮询 |
| R2 | Markdown 渲染 | towxml + §7.4 受限规范；规范外内容默认主题兜底 |
| R3 | 衬线字体 | §7.3 子集化 + `wx.loadFontFace` + 系统字体降级；不追像素级还原 |
| R4 | 订阅消息为一次性授权 | 在「开始聊」「生成报告」两个高意愿时机请求授权（一次可勾选多模板）；授权余额入 Redis 计数，无授权时报告完成仅站内未读态兜底 |
| R5 | 米诺主动写报告误触发 | §8.4 显式标记 + 每日上限 |
| R6 | streak 时区/断签 | 统一 Asia/Shanghai 计算日界；`last_active_date` 落库，Redis 只做快路径；断签清零在首次当日活跃时惰性结算 |
| R7 | **合规（必须并行启动，可能是上线关键路径）** | 生成式 AI 内容：接入 `msgSecCheck` 审用户输入、对 LLM 输出做安全审核钩子；小程序类目与生成式 AI 相关备案/申报材料尽早准备；登录页《用户协议》《隐私政策》勾选；报告仅本人可见、提供删除 |
| R8 | 登录/入局页无高保真稿 | §11 开放问题 4：按 token 自拟低保真（纸底 + 印章 logo + 微信绿登录按钮 + 三字段入局表单），实施前出一版补充设计 |
| R9 | FastGPT 单点 | 后端对 FastGPT 调用统一封装（超时/重试/熔断）；对话失败给「米诺正在闭关」友好态；报告 job 失败可重试 |

## 10. 实施里程碑（建议 6 个阶段）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0 地基**（0.5 周） | monorepo 脚手架（`miniprogram/` + `server/`）、Docker Compose（pg/redis/FastGPT）、CI（lint+test）、tokens.scss | 双端可跑 hello；CI 绿 |
| **M1 骨架**（1 周） | 微信登录 + JWT + 入局页 + 自定义 2 tab + 基础组件（nav-bar/tab-bar/卡片） | 新用户走通 登录→入局→空对话页/空报告库 |
| **M2 对话 MVP**（1.5 周，核心） | FastGPT 米诺应用配置（V6.0 浓缩提示词）；后端 SSE 透传；对话页流式 + suggestions；真机双端流式验证 | 真机与米诺流畅对话，风格符合人格铁律 |
| **M3 记忆**（1 周） | 每用户知识库创建、`kb.ingest` 要点写入、检索接入上下文 | 跨会话提及旧信息，米诺能接住 |
| **M4 报告**（1.5 周） | 报告工作流 + 异步生成（BullMQ）+ 生成弹层 + 列表/筛选/未读 + 详情双版式 + 「聊这份报告/补充」回流 | 两种触发都产出符合版式规范的报告并回流对话 |
| **M5 回访**（1 周） | 今日一问 cron + `prompt_seed` 开场 + 订阅消息（今日一问/报告完成）+ streak | 次日收到推送→点进→开聊→streak +1 |
| **M6 打磨与送审**（1 周+审核周期） | 分享/导出、异常态/空态、内容安全接入、合规材料、体验测试、提审 | 通过微信审核，线上完整闭环跑通 |

关键依赖提前项：微信小程序主体资质与类目、订阅消息模板申请、FastGPT 部署与模型 API key、域名+HTTPS+ICP 备案（request 合法域名）——**M0 时并行启动**。

## 11. 产品决策记录（2026-07-10 已拍板）

1. **FastGPT 部署方式**：**自托管**，进 Docker Compose。
2. **底层模型**：产品方后续自行接入模型 API 与密钥；代码中一律走环境变量/配置占位（`FASTGPT_BASE_URL`、`FASTGPT_APP_KEY` 等），不硬编码任何厂商。
3. **后端**：确认 NestJS。
4. **登录/入局页视觉**：由实施侧按宣纸水墨 token 自拟（纸底 + 朱砂印章 logo + 微信绿登录按钮 + 昵称/行业/生意背景三字段入局表单），登录方式仅微信登录。
5. **导出形态**：应用内预览 + **图片分享图**（canvas 绘制宣纸风格长图，可保存相册/转发微信）。小程序无原生 PDF 生成能力，不做 PDF；`GET /reports/:id/export` 提供绘图所需结构化数据，绘制在小程序端完成。
6. **随机邀约（米诺突然找你）**：二期。
7. **「我的」tab（2026-07-10 追加）**：按 V2「07 我 · 成长」屏视觉适配恢复第 3 个 tab；游戏化数据支柱（段位/里程碑/评分）全部删或换为 V3 真实数据（streak/报告统计/画像）；`GET /me` 增加 `createdAt` 供「相伴 N 天」；设置分组承载通知授权、协议/隐私、退出登录与删除账号（DELETE /me）。
